# Account cloud metadata and immutable selection spool

The cloud queue now stores jobs, typed response/retry state, controls, receipt checkpoints, progress, receipt associations, continuations, quota reservations and immutable-file accounting in `cloud-metadata.sqlite` under the captured account's upload directory. `source-progress` namespaces share that same database. SQLite uses WAL and `synchronous=FULL`; the database, WAL and immutable files use protection compatible with operation after first unlock. Queue suspension closes its connection after fencing callbacks.

## Migration and replay authority

The initial import copies one legacy metadata value at a time inside a single transaction, verifies the bytes read back from SQLite, and commits the migration authority marker with those rows. A failed transaction does not publish the marker. The SQLite authority is then exclusive; retained legacy `.json`, `.control`, `.progress`, `.receipt`, `.selection` and `.continuation` files are never re-imported. This prevents an old retry or receipt file from reviving settled debt. The import never resets, truncates or deletes a database.

Legacy files remain untouched as recovery evidence. Their occupied bytes stay in quota accounting. Unknown formats, duplicate lanes, ownership mismatches, corrupt metadata and missing/corrupt bodies fail closed. An unknown or duplicate legacy selection is checked before any selection conversion is published. Existing body bytes, prepared selection identities, job identities, manifest membership and exact wire digests remain unchanged; old compressed payloads are replayed without recompression.

## Bounded loading and spool publication

Startup retains compact lane indices and small continuations, not every decoded selection. Legacy startup reads only scalar membership metadata from its JSON; it does not decode base64 bodies, hash them or create spools. Its conservative reservation uses the saved encoded length until admitted per-lane conversion validates the complete original selection. Recovery enumerates IDs and loads one full selection at a time; the journal cache holds at most one decoded lane. Each selection's `Data` fields stream into one immutable digest-keyed segment. Its SQLite manifest stores offset, length and SHA-256 references instead of base64 copies of raw and compressed data. Decoding verifies the segment and each reference, then applies the existing canonical selection and membership validation. The saved raw rows and wire bytes each remain available for exact replay; they are not expanded into base64 in the stored manifest.

A spool publication records capacity before creation, fsyncs the completed segment, records a durable rename intent, renames and syncs the directory, then atomically publishes the manifest, index, continuation and exact file accounting. A crash before publication can only leave a derived, unpublished preparation file; its durable intent identifies both possible names. Recovery can discard that unreferenced preparation without touching the canonical source rows or any published selection. A published spool is removed only through receipt-authorized source settlement. A separate durable retirement record survives an unlink failure or crash. Shared digest files remain while another selection references them.

File byte/count totals update transactionally through SQLite triggers. Quota admission reads these totals and indexed metadata sizes; it does not recursively rescan and hash every queued body. The initial legacy import is the one directory inventory pass. SQLite allocation and WAL sizes are included. Unknown/orphan legacy files remain counted conservatively. Retained legacy evidence can consume space until a separately reviewed retention policy removes it.

Loaded job debt enters the shared resource budget before new preparation can begin. The queued-byte/job threshold blocks fresh source selection; it does not block loading existing selections, recovering saved receipts or settling committed debt. Those operations still respect history, heat and the other bulk-work limits. A verified receipt can therefore release its exact selection when the preparation queue is full, without admitting unrelated new source work.

## Validation and limits

The native harness extends the existing queue/outcome tests with legacy authority and account fencing, transaction rollback/accounting, exact legacy wire replay, 24-lane lazy loading, a separate 32-lane synthetic RSS report, startup under denied preparation, corrupt spool preservation, receipt-authorized retirement after unlink failure, shared progress migration, and injected interruption after segment fsync, rename-intent commit and rename. A 128-job regression saves a verified receipt, relaunches, rejects fresh selection, recovers the receipt without network, and settles progress plus exact cleanup to reopen admission. It runs `PRAGMA integrity_check` on synthetic stores after recovery. The existing prepared-selection crash and preference tests now inspect SQLite metadata rather than obsolete files; their synthetic directories are removed after open SQLite owners leave scope.

Run `zsh Tests/CloudUploadNative/run.sh /external/artifact-directory`. Source hashes and exact source head are recorded with each run. Full app-hosted prepared-selection tests and the exact Release/CI run must also pass before promotion. Synthetic tests do not establish power-loss behavior, actual ENOSPC, iPhone RSS, energy, battery or locked background execution.

Per-selection encoding, canonical identity validation and legacy migration can still temporarily allocate a complete bounded selection. This change makes retained selection memory independent of total queued body bytes, but does not claim constant memory with respect to the size of a single legacy job. Large legacy jobs remain replay-compatible rather than being silently split or re-encoded. Physical large-backlog RSS, thermals, battery and throughput: `NOT_MEASURED`.

## Fresh-source byte admission and optional completion negotiation

Fresh binary jobs reserve a 4 MiB decoded allowance, 64 KiB codec allowance, and 16 KiB intent/renewal overhead before source materialization. SQLite length/keyset queries select a byte-bounded prefix in the same read snapshot before loading PPG, auxiliary, or raw BLOBs. Append pages similarly bound source text; mutable replacement windows fail closed as a complete window instead of truncating authoritative replacement data. IMU source reads check the wake deadline between members/segments and archive lengths before loading archive BLOBs. Empty lanes refund unused byte reservations so a fixed traversal cannot starve later debt. The deadline still bounds scans.

An unsplittable first source member records an account/receiver/source/lane-scoped compatible-encoding pause. It never skips the row, advances its cursor, or removes source data. The UI exposes the pause; retry requires explicit resolution/resume. Existing immutable selections retain their original payload, identity, and limits; one older oversized transfer may be admitted per wake so those saved jobs remain drainable.

The optional `objectLane.completionModes` capability can advertise `async-v1`. Only a well-formed known mode list enables it. The mode is captured in each new immutable selection/job; absent legacy fields remain synchronous and are omitted when encoded. Only the completion POST carries `Noop-Push-Completion: async-v1`. A pending HTTP503 with Retry-After persists one retry outcome; neither it nor PUT success can advance source data. Exact receipt validation is unchanged.

At this checkpoint source arrays and prepared jobs are bounded, and backlog restoration loads at most one selection. Direct streaming serialization/compression into the transfer file is a separate implementation stage; this checkpoint does not claim it. Physical energy, thermal, and device RSS gates remain NOT_MEASURED.
