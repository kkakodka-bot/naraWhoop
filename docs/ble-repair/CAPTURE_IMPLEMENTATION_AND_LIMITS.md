ResourceBudget now admits bounded cloud control/ready transfer work during healthy capture/history without granting heavy maintenance. Nominal foreground uses at most two total transfer slots, with queue fairness reserving room for fresh/control work. Heat, storage, network policy and actual finite opportunities remain enforced. Typed opportunities expire on their original deadline; nil cached background deadline is not a grant. Collector's engineering coalescing deadline is 200 ms; no measured BLE-to-durable p95 is claimed.

A real notification/restoration/lifecycle callback creates at most one coalesced two-second application window. UIKit invalid/expired assertions revoke it. Local bounded passes run independently of network completion; ordinary transfers borrow only already-admitted event work and never extend the original deadline. Application timers provide no guarantee while suspended. Retired account writers retry only their captured owner/store during admitted wakes; current-account capture stays gated until retained data settles.

Current app tests cover these repairs, deadline joining, invalid UIKit assertion, generation-fenced standard callback, retained retired writer and actual store transaction. Separate CloudUploadNative evidence is owned by the release reviewer.

The raw pending-byte admission query is O(pending raw rows), the immutable outbox budget is 128 MiB, and fairness/admission defaults need realistic sustained-debt/target-phone/VPS measurements. No model promotion, phone install/reset/launch, production migration/deployment, four-hour locked run, 24/72-hour soak or 1,000-user readiness claim occurred in this subtask.
