# Five-minute HRV contract

`HrvWindow` and `PhysiologyQuality` are paired Swift/Kotlin implementations. The server kernel copies the Kotlin files byte-for-byte from Android. `hrv_window_oracle.json` is shared across Swift, Android and server tests.

## Evidence and estimates

Windows are UTC-aligned 300-second half-open intervals. Immutable original interval identity includes user/device/source, firmware, original value, endpoint beat identities, continuity group, packet identity/ordinal, decoder/clock versions and timestamp precision. A successive difference requires two accepted original intervals sharing one original endpoint and three distinct accepted original beats. Rejected endpoint status propagates wherever that beat appears. Replayed identities are deduplicated; conflicting replays are unavailable independent of arrival order. Numerical RR equality is not an identity key.

`observedTimeFraction` is the clipped union of verified original spans divided by 300. Duplicate/overlapping spans cannot increase it. `maximumGapSeconds` includes both edges. Accepted-duration and accepted-original-interval fractions remain separate. Corrections retain cumulative pass/event accounting and a distinct corrected pair mask/count/method version; corrected values never add observed acquisition time. Original RMSSD, corrected RMSSD, five-minute SDNN and research-only partial-pair RMSSD are distinct fields. Valid zero and clean high variability remain intact.

The current measurement method is `observed-pair-rmssd-v3`, with quality policy `engineering-multisignal-90-v3`. Its engineering gates require 90% observed time, 90% accepted original intervals, 80% accepted duration, at most 10% affected originals, maximum gap 30 seconds, and at least 20 pairs. The accepted-duration gate prevents many short valid intervals from hiding one long uninterpretable span. Coverage/correction/gap thresholds require participant-disjoint development and held-out reference qualification; these are not validated WHOOP cutoffs. IBI plausibility remains 250–2500 ms, with no blanket Malik filter or HRV ceiling.

Every observed and corrected pair requires verified timing for both constituent original intervals. Any mixture of verified and unverified timing abstains with `mixed_verified_unverified_timing`; an unverified interval cannot influence a research pair, SDNN, or corrected estimate. Corrections cannot bridge deleted events, rejected endpoints, missing acquisition or reconnect boundaries. Packet-local identity without a beat clock now has zero timing-qualified pairs.

Available, time-aligned motion contamination, contact rejection, optical-quality rejection, and detector disagreement cause explicit abstention. Missing quality channels are reported in `unavailableQualitySignals`, never labelled clean. A sustained run of at least 20 extreme alternating transitions, exceeding both 250 ms and 35% of the local mean IBI, is `rhythm_ambiguity`. This unvalidated engineering screen preserves original/research evidence; it diagnoses neither ectopy nor arrhythmia. High variability without that pattern and genuine zero RMSSD remain numerically intact. Reference evaluation must measure both false rejection of clean high HRV and retained coverage.

The physiology input readers retain eligible source candidates. `HrvSeries.selectedWindow` independently qualifies each source in each UTC five-minute window, using stable history-before-standard preference only among qualified sources. A sparse history row cannot suppress a qualified standard-source window elsewhere in the night. Partial sources are never spliced; the legacy reader retains its separately named compatibility policy. Night summaries and baselines continue to abstain across incompatible source or acquisition identities.

Current historical RR storage does **not** meet the trusted timing contract. The legacy adapter therefore reports `continuity_unverified`. The additive `RRPacketProvenance`/`RrPacketProvenance` companion lane now preserves CRC-checked original bytes and word indices through actual native decode, SQLite, versioned append export, receiver projection and the server observation bridge. `PhysiologyQuality.checkedPackets` emits packet-local identities only for complete declared arrays of 1–4 words, retaining zero words as rejected original slots and endpoints. It does not compact a rejected word into false adjacency. The older `historicalPacket` convenience adapter still refuses compacted/count-mismatched input.

Coarse packet seconds and mapping uncertainty are retained, but no subsecond spans or inter-packet continuity are invented. Checked packets expose local pair evidence but remain `timing_coverage_unverified` as five-minute measurements. Production qualification still requires verified acquisition-clock/cross-packet evidence; immutable packet identity itself is now wired rather than deferred as an external blocker. Neither a device catalog's current firmware nor a client's uploaded timing assertion is promoted into historical capture evidence.

## Context and summaries

Measurement validity does not require a sleep label. The V1 stage feature reader consumes only valid shared measurements, never pooled coarse RR. In retrospective mode a feature is the valid UTC five-minute measurement containing the epoch. Missing features remain NaN. Provenance-aware staging bypasses old fingerprints that do not contain that provenance. The V2 RSA regularity adapter is a separate respiration ownership path.

After final binary sleep/wake state and main-night/nap ownership are known, the engine derives shadow context using `contextFromSleep`, or honors explicit caller-supplied context. Unknown state stays unknown; sleep stages are not a deep-only eligibility gate. Causal context needs an `availableAt` timestamp no later than the measurement end, and the engine emits only windows completed by its observed-through cutoff. Retrospective and causal modes are explicit and baseline-isolated.

Nightly HRV is the arithmetic mean of eligible full five-minute main-sleep windows. Naps/rest are separate contexts. Median, distribution, accepted duration, duration-weighted diagnostic mean, total opportunity coverage and coverage in each episode third are retained. The initial representativeness policy requires at least three windows, 50% overall coverage and 10% coverage in every third. A dense early island cannot qualify a whole night. The old deep-only preference cannot replace this primary statistic, and a cached/vendor scalar cannot silently enter the canonical RMSSD series.

The personal comparison uses `past-night-log-median-mad-v2`. It isolates user, physical device, known capture firmware, source, modality, method, quality policy, decoder/clock versions, duration, context and computation mode. Observations less than 12 hours before the current window are excluded as potentially belonging to the same episode. Remaining adjacent windows separated by less than 12 hours form one observation block; each block contributes one median positive log-RMSSD. This conservative separation rule accommodates shift and split sleep without a fixed bedtime, but is an engineering independence proxy requiring reference study.

Defaults are 28 prior days and 20 effective independent blocks, not 20 five-minute windows. Positive lag-one autocorrelation reduces effective sample count by `floor(n * (1-rho)/(1+rho))`; negative correlation never increases it above the independent count. `independentNightCount`, `observationCount`, `lagOneCorrelation`, effective count, excluded zeros and insufficiency reasons expose the denominators. For nap/quiet-rest contexts the count describes separated observation blocks rather than measured nights. Serially correlated history cannot silently mature a baseline. Future observations, current-episode observations, conflicting revisions and incompatible series are excluded. Zero measurements remain zero without an invented log floor. No recovery-score formula was redesigned.

## Integration and checks

`AnalyticsEngine.analyzeDay` accepts optional `hrvObservations`, `hrvContext`, `hrvHistory` and `inputRevision`. `DayResult` returns `hrvMeasurements`, aligned `hrvBaselines` and optional `hrvNightSummary`. Legacy current-HRV callers remain source-compatible but unavailable until proven input is supplied. Proven `CurrentHRV` reads the latest completed UTC window rather than pooling 30 minutes.

Scoped Swift and server Kotlin suites verified the shared 16-case measurement oracle, packet-local adapter, true zero/high variability, correction provenance, source switches, replay/order independence, gap edges, baseline isolation and summary arithmetic. Integration tests cover cached vendor-value exclusion, quality-only stage features, final binary context without annotations, legacy unavailable reasons and causal future exclusion. An intermediate full-package run on 2026-09-18 passed 1,905 Swift tests with zero failures and 786 Kotlin kernel tests with zero failures/errors and five fixture skips; the HRV/provided-sleep subset then passed 24 tests. These are historical checkpoints, not the final count after subsequent review fixes. Earlier assertions that expected unproven legacy HRV were migrated to the unavailable contract while retaining positive proven-input tests. Logs are `/Volumes/Untitled/physiology-build/analytics-full-tests.log`, `analytics-kotlin-full-tests.log` and `hrv-tests.log`; the final verification ledger supersedes these counts.

Both native HRV detail screens now expose the selected server's five-minute RMSSD windows separately from the labeled local daily history. Typed cache projections fence owner/device/version/revision, preserve valid zero and high values, display context and baseline eligibility/effective sample count/deviation, and leave missing/conflicting buckets unavailable. They do not manufacture a five-minute series from a daily scalar or imported SDNN. Active/mixed windows remain visible measurements but cannot become stable-rest baseline comparisons. Source, method, observed time and per-window observed coverage accompany the readings. The current unqualified beat clock can therefore produce an honest unavailable series rather than a fabricated trend.

No ECG/PSG physiological-accuracy promotion, real-device continuous capture, verified raw-object retention, or deployment is claimed. The native implementation is censor-only; an auditable Lipponen–Tarvainen comparator remains a separate W4/model adapter, evaluated by W5 on reference data. A package green is not evidence that the current phone/server RR rows suddenly gained missing timing provenance.
