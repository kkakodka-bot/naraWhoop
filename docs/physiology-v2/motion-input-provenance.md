# Receiver motion evidence

Migration `20260918234000_motion_evidence_provenance.sql` adds nullable `motion_evidence_version` and independent `orientation_evidence_version` to gravity projections without rewriting historical values or raw bytes. Historical rows remain null because older receivers converted explicit null, false and empty strings into numeric zero in both dynamic acceleration and XYZ. A plausible stored vector such as `[0,0,1]` therefore cannot prove genuine orientation, just as a stored dynamic-acceleration zero cannot prove stillness.

The updated receiver requires an actual safe-integer numeric timestamp and finite numeric X/Y/Z values. It accepts dynamic acceleration as motion evidence only when the submitted value is genuinely numeric, finite and within the engineering input range 0–8 g. A genuine numeric zero is retained. Missing, boolean, string, nonfinite and out-of-range inputs produce null dynamic acceleration and null proof; an input-supplied proof label is ignored. Accepted input receives `projected-dynamic-acceleration-g-1`.

The receiver independently sets `projected-gravity-g-1` for checked numeric timestamps and XYZ, including new orientation-only rows with no dynamic acceleration. Uploaded proof labels cannot substitute for these type checks. The v2 server reader includes orientation only with this proof and exposes dynamic acceleration only with its separate proof version. This receiver's motion proof also requires orientation/timestamp proof; an unknown orientation cannot acquire motion proof through a scalar-only database update. Legacy orientation, zero and nonzero dynamic-acceleration values remain stored but unavailable to the new physiology path. The separately deployed legacy scorer remains unchanged. Adding or removing either proof atomically dirties the existing scoring/input revision through the complete-row projection trigger. No migration backfills proof from scalar values.

Deploy the additive migration before the updated receiver/scorer. Older receiver writes remain compatible but cannot attest motion. Raw-source reprocessing may qualify historical rows only if it verifies the original field types, decoder semantics and units; bulk-labeling old zero rows is not qualification.

This marker establishes a checked numeric projection contract, not optical contact quality, waveform synchronization, absence of between-sample movement, or reference accuracy. The range and contamination thresholds remain unvalidated engineering policies. Existing impossible-gravity and stale-sensor policies apply independently.
