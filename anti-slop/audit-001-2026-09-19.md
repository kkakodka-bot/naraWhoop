# Afterward visual/source audit

Scope: performance changes after PR #22 head `279383a0ef505f43a318d1d67596cdd9c4bfe835`.
The user chose audit-afterward mode. No aesthetic redesign was requested or applied.

## Findings and approved corrections

1. **HIGH — missing-image fallback, R-34/R-35.** In `SleepView.swift`, the new photo-presence check is reliable on UIKit, where image decoding can fail with nil. The non-UIKit resolver always constructs `Image("sleepNightHero")`, even if the resource is missing, so it can suppress the previously visible procedural fallback. Preserve the macOS fallback or validate its image before suppressing it. This is a conditional source-level regression, not an observed failure with the installed iPhone assets.
2. **MEDIUM — refresh sequencing, R-35 verification gap.** Sleep now awaits cloud readback before starting local refresh. A slow network response can delay the local part of this action. Start these independent reads concurrently, or retain local-first behavior. End-to-end latency has not been measured.

The user approved both corrections. Follow-up: (1) non-UIKit always retains the original procedural base; only UIKit's validated photo suppresses it, and (2) structured concurrency starts the cloud request while local refresh proceeds independently. Cancellation remains structured and both operations are awaited. No layout, color or unrelated aesthetic changes were made.
